## A. 发布阻塞项（发版前必须清掉）

### A1. JetBrains Mono 许可证副本缺失
- **现状**：内嵌字体三份均 SIL OFL 1.1（Archivo latin 子集 18.3KB、Noto Sans SC CJK 子集 1.72MB、JetBrains Mono latin 子集 30.7KB）。Archivo 与 Noto 的许可证文本已随仓库分发（`frontend/src/assets/fonts/OFL-*.txt`），**JetBrains Mono 的许可证副本仍缺**。
- **影响**：OFL 要求随分发字体附带许可证，缺它不满足再分发条件。
- **处置**：发布前从 JetBrains Mono 官方仓库取 OFL.txt，放入 `frontend/src/assets/fonts/`（随 `assets` 打入前端产物）。

### A2. 真机验证全未跑
- **现状**：24 条验收用例（12 条发布阻塞 ★）全部「已实现、待真机验证」。`go test` / 九道组件门禁 / 三组页面门禁全绿，但从未在真实 exe + 真实模型上跑过端到端用例。
- **影响**：Win32 进程行为（CTRL_BREAK 送达、Job Object 杀进程兜底）、llama-server 实际推理质量、显存峰值都未在真机上确认。
- **处置**：按 `docs/04-交付与验收方案.md` 逐条执行；F-17/F-18（M4）约 0.5 天，F-08（M5）约 1 天含模型下载。
- **记录基线**：exe 于 2026-10-09 18:08 重建（`b50c496`，20,705,280 字节，嵌入自检通过），**含 M4 全部 + M5 接入 + QA 修复 ×6**——真机验证即以该构建为基线。（旧基线 2026-10-09 16:43 构建已被替换，不含 QA 修复。）

### A3. 性能阈值未校准
- **现状**：01 文档 §3 性能表全表为 `[assumption]` 目标值（TTFT ≤800ms、吞吐 ≥30 tok/s、模型切换 ≤15s、字幕队列 ≥5 条/s），无实测数据。
- **影响**：发布的性能承诺目前是推断不是测量。
- **处置**：实机采集后替换表格（采集点位：主翻译台单次翻译后读 `tok/s · TTFT`（`MainTranslate.tsx:569`）、模型中心切换计时、字幕队列进度事件斜率、`doc:progress` 字符斜率），并标注硬件（GPU 型号/驱动/模型档位）。

## C. 用户可见的功能限制（不阻塞验收，按里程碑排期）

### C1. 术语本只读，可选不能建/改/删
- **现状**：约束抽屉用 `ListGlossaries` 拉列表；`SaveGlossary`/`DeleteGlossary`/`ExportGlossaryCSV` 后端齐全、`wailsapi.ts` 已封装，但**界面未接**——术语只能导入 CSV 落地后选用。
- **影响**：用户无法在应用内维护术语库。
- **处置**：M6 后或独立小里程碑接术语管理 UI（组件层已有 Modal/表单原语）。

### C2. 配音模型用通用提示词驱动
- **现状**：`homura`/`nailong` 激活后主翻译台仍用通用翻译提示词；模型中心有警告条如实说明。官方领域模板（`translator/prompt_homura.go`/`prompt_nailong.go` 已存在）尚未接到前端选模型路径。
- **影响**：两模型的领域特性在 UI 上发挥不出。
- **处置**：后续里程碑（分发逻辑按 `translator.ModeKind` 已就绪，缺前端选择面）。

### C3. 状态栏「离线可用」徽标是静态元素
- **现状**：徽标写死显示（`StatusBar.tsx:93`）；Go 侧 `GetSystemStatus` 的 `Offline` 字段恒为 `false`（`app.go:646`）且前端无人消费——**断网探测并未实现**。徽标只是把「模型就绪后不需要网络」这句设计事实常驻显示。
- **影响**：用户可能误读为实时断网状态。
- **处置**：要么实现探测（断网时本地推理照跑、下载失败即离线），要么改文案为「本地推理」，排期时定。

### C4. 模型激活收口只在 UI 层
- **现状**：模型中心已放开「文件已登记即可设为当前」（`ModelHub.tsx:200` 起），但后端 `SetActiveModel` 本身没有守卫——绕过 UI 直接调用仍可设置任意模型（含未登记路径）。
- **影响**：只有直接操作绑定层的调用方受影响，正常 UI 路径无风险。
- **处置**：后端补登记校验可作健壮性小项，非阻塞。

### C5. 设置页「关闭程序时」是单选展示
- **现状**：无 `onChange` 的单选组——「退出即释放」是唯一实现；`config.Resource.CloseBehavior` 无其他分支。主题与字号则已真正可改并持久化（`Settings.tsx:163`，存 localStorage + 配置 `appearance`，重启保持）。
- **影响**：关闭行为不可配置（目前无其他行为可选）。
- **处置**：若未来加「常驻」选项再接线；当前如实展示不算缺陷。

## E. 性能与测量的未定项

1. **64K 档（`-c 65536`）真机未测**：模型 GGUF 标称 262144 positions（理论支持），但启动耗时、显存峰值、失败时 orchestrator 退避从未实测；`-c` 自定义刚落地时，建议首次用超 32K 档时手工观察一次。
2. **显存估算是线性模型**（`vramestimate.EstimateCtxVRAM` 的 `basis` 字段如实标注）：偏差 ±20%，不是测量值；F-08b 的「64K 需 12GB+」提示按估算式给出。
3. **大文件边界**：字幕 `MaxSubtitleBytes` 32MB（`engine.go:18`，B29 有意设计——防误选整本小说）、长文档单卷 50000 字（超限有明确 toast 提示）。两者均有友好报错，属设计边界非缺陷。
4. **日志内容随级别变化**：`logs/llama-server.out.log` 默认不进「一键收集打包」的脱敏 zip（`app/logs.go:15`）——实测样本 25 行只有启动信息无正文，但 `-lv` 级别提高后的行为未实测；该日志含模型绝对路径，分享 zip 时等于交出本机目录结构，默认排除是正确选择。

## F. 工程与测试约束

1. **`go test -race` 不可用**：`CGO_ENABLED=0` 是架构决策（ADR-001），竞态类修复只能靠确定性并发测试 + 代码审阅。**任何报告不得声称 race detector 通过**。
2. **playwright chromium 本机不可达**（`cdn.playwright.dev` 超时）：各 verify 脚本内置回退 `channel: 'chrome'` → `msedge` → 自带 chromium，不依赖浏览器下载；这段回退在每个脚本里各存一份，没有抽公共 helper。
3. **Git Bash 跑 node 门禁脚本需 `MSYS_NO_PATHCONV=1`**：只有 `verify-a11y.mjs` 的位置参数 `/?primitives` 会被 MSYS 路径转换吃掉；npm scripts 走 cmd 则不需要。

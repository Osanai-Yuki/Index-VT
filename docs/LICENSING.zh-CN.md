## 协议选择依据与比较

本项目选择 **MIT**，便于使用、修改和分发，同时减少个人维护的许可管理负担。以下保留 MIT、Apache-2.0 和 GPL-3.0 的比较，供理解选择依据；只有根目录 MIT `LICENSE` 是本项目采用的协议，比较不构成双重或多重许可。

| 方案 | 适合的偏好 | 主要影响 |
| --- | --- | --- |
| [MIT](https://choosealicense.com/licenses/mit/) | 简单、宽松，允许商用与闭源衍生分发 | 保留版权和许可声明；不要求公开衍生源码。 |
| [Apache-2.0](https://choosealicense.com/licenses/apache-2.0/) | 宽松分发，同时提供明确的专利许可条款 | 保留许可，标明修改，按上游情况处理 NOTICE；不自动取得商标使用权。 |
| [GPL-3.0](https://choosealicense.com/licenses/gpl-3.0/) | 希望受其覆盖的分发衍生作品继续提供源码 | 分发时履行源码和同协议义务；具体组合需检查兼容性。 |

这些方案都不等于“禁止商用”。如果希望禁止商用或只允许某类用途，应另外定义授权条件，也不应把它标为一般意义的开源协议。权利与义务以选定协议全文为准。

## MIT 与 Apache-2.0 的详细区别

两者都允许他人使用、修改、商用、销售和闭源分发，也都允许你继续销售自己的软件。选 Apache-2.0 不会自动要求别人公开修改源码，选 MIT 也不代表放弃版权。基础条款见 [MIT 标准文本](https://opensource.org/license/mit) 和 [Apache-2.0 标准文本](https://www.apache.org/licenses/LICENSE-2.0)。

| 比较点 | MIT | Apache-2.0 |
| --- | --- | --- |
| 版权与许可声明 | 软件副本或实质部分须保留版权及许可声明 | 分发时给出协议副本，源码形式的衍生作品保留相关版权、专利、商标与署名声明 |
| 明确的专利授权 | 正文没有单独写明专利授权条款；不能仅由此断言所有法域下一概没有隐含许可 | 第 3 条明确授予贡献者有权授权、且其贡献本身或与所提交作品组合所必然涉及的专利权利 |
| 专利诉讼终止机制 | 没有相应的专门条款 | 针对该作品或纳入的贡献发起所述专利侵权诉讼时，终止就该作品授予你的相关专利许可；不是任何纠纷都会触发，也不是自动终止所有版权许可 |
| 改动标识 | 没有要求修改文件必须注明改动的专门条款 | 第 4(b) 条要求修改过的文件显著注明已修改；不等于必须公开所有源码或逐条公开提交记录 |
| NOTICE | 没有独立的 NOTICE 处理机制 | 上游发行物含 NOTICE 时，按第 4(d) 条保留其中相关署名信息；可放在 NOTICE、随附源码/文档或适当显示位置，并非所有项目都必须凭空新建 NOTICE |
| 商标 | 没有专门的商标授权条款，不能据此当作任意使用品牌的许可 | 第 6 条明确不授予一般商标使用权，仅保留描述来源、复制 NOTICE 等合理需要 |
| 提交外部贡献 | 正文没有专门定义提交贡献时的默认授权规则 | 第 5 条为有意提交纳入项目的贡献规定默认适用本协议，并保留明确例外及另行协议的空间 |
| 免责 | 包含不提供保证与责任限制 | 同样包含不提供保证与责任限制，且有更详细的定义和条款 |
| 维护成本 | 文本短，最主要是维护许可证与版权声明 | 需额外留意修改标识、NOTICE 与专利相关条款；可以按需要使用文件头或 SPDX 标识 |

Apache-2.0 的专利授权不是“全世界的专利保险”，不覆盖任意第三方专利，也不是把贡献者所有专利都交给用户。MIT 的简短不能替代对专利问题的具体判断。适用范围和触发条件以 [Apache 第 3 条](https://www.apache.org/licenses/LICENSE-2.0) 及 [ASF 专利范围说明](https://www.apache.org/foundation/license-faq.html#PatentScope) 为准。

### 放到 Index-VT 上看

- **别人把你的程序改成收费闭源版：**两种协议原则上都允许。MIT 要保留适用的版权/许可；Apache 还需遵守改动声明、相关 NOTICE 等条件。两者都不保证对方为你分成、免费提供改版或合并回主仓库。
- **你以后接受企业贡献：**如果希望贡献涉及的必要专利有明确授权路径，Apache 的规则更具体；但选择该协议本身不要求你照搬 Apache 基金会的整套管理制度。MIT 更简洁，贡献权利与专利问题可以另外管理。
- **想保留作者名字：**两者均保护相关声明的保留。它们不强制首页展示醒目广告式鸣谢，也不替代 Git 提交身份管理。Apache 协议中的 Contributor 定义不是 GitHub Contributors 的自动名单。
- **希望项目别被闭源商用：**两者都不满足这个目标。若希望分发衍生版本时也公开相应源码，可另评估 GPL；如果目标是全面禁止商用，则不属于这两种宽松开源方案。
- **担心模型本身用 Apache：**不需要仅为匹配模型而把原创 GUI 也改为 Apache。分别保留模型、字体、运行时和代码的适用条款；若直接复制上游源码/提示材料或打包分发，还要核查对应文件的具体许可。

### 文件准备的差别

**采用 MIT：**根目录放标准 MIT `LICENSE` 和作者版权；README、包元数据与发行说明统一标记 MIT。第三方许可证照常单独保留。

**采用 Apache-2.0：**根目录放完整 Apache-2.0 `LICENSE`，按适用内容处理版权/文件声明；上游已有 NOTICE 时保留相关信息。可以给自己的项目增加简洁 NOTICE，但不应把它误认为许可生效的普遍必需文件，也不要把新限制写进 NOTICE。官方应用方法见 [ASF 指南](https://www.apache.org/foundation/license-faq.html#Apply-My-Software)。

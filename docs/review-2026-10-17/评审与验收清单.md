## 2. 用户体验检查清单

以下为空白验收表，不表示这些能力当前全部缺失。每项记录：通过 / 失败 / 不适用、环境、操作、实际结果、证据文件、关联问题。

原则参考 [Nielsen 可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)：状态可见、用户控制、一致性、防错、出错后可恢复。检查项针对本项目具体化。

### 2.1 下载与校验

- [ ] D01 下载前能看懂模型用途、下载大小、落盘位置、剩余磁盘空间；不足时提前给解决方法。
- [ ] D02 源探测 / 下载 / 校验 / 可使用分别呈现；100%下载后仍明确“正在校验”，不提前允许使用。
- [ ] D03 已下载大小、总量、速度可理解；未知总量使用不定进度，ETA 标注估计，停滞不显示假速度。
- [ ] D04 断网、超时、切源后，用户知道保留了多少、接下来会续传还是重下；恢复联网可重试。
- [ ] D05 暂停、继续、取消语义不同且实际有效；取消前后说明临时文件保留策略；不能无提示删数 GB 已下载内容。
- [ ] D06 校验不通过与“无法取得校验信息”分开说明；只提供安全恢复路径，不把跳过校验作为默认解法。
- [ ] D07 重复点击下载不会创建重复任务；重启后 `.part` 能否续传有明确行为；完整模型不会无故重下。
- [ ] D08 下载成功有稳定的“设为当前 / 开始翻译”下一步；导入本地文件的识别失败可修复，用户不必猜文件名。

### 2.2 显存与模型运行

- [ ] V01 区分“显卡总占用”“本应用占用”“启动估算”；未测得的值不显示为0，不用估算冒充实测。
- [ ] V02 选择模型/上下文前展示预计需求和可用资源；估算不足时给降低上下文、换量化或CPU等具体选项。
- [ ] V03 冷启动有“加载模型”状态；首次耗时与后续热启动分开解释，窗口与取消操作仍响应。
- [ ] V04 模型切换时明确当前任务如何处理；不会无声杀掉任务，禁用按钮说明原因。
- [ ] V05 空闲释放不会中断活跃任务；释放后下次任务自动唤醒；用户无需把正常休眠当成故障。
- [ ] V06 OOM、驱动异常、子进程崩溃可识别且可重试；如自动降低参数，明确告诉用户最终使用了什么。
- [ ] V07 CPU模式能正常完成代表性任务；耗时提示基于测量，不能把固定“慢10倍”当所有机器的事实。
- [ ] V08 正常退出、主程序异常退出、重复启动后无孤儿推理进程；显存恢复到接近启动前基线，而非要求系统总显存归零。

### 2.3 任务取消、暂停与恢复

- [ ] C01 开始后立即反馈并防重复提交；取消在加载、首字等待、流式输出、队列执行各阶段都可达。
- [ ] C02 “暂停”停止后续推进且可继续；“取消”结束本轮；“重新翻译”会重新计算，三个词不混用。
- [ ] C03 点取消先进入“正在停止”，后端确认后再显示停止；设可测的响应目标，UI反馈建议≤100ms，后端耗时另测。
- [ ] C04 已生成文本和已完成块保留，并标出未完成；能复制或明确标注后导出部分结果。
- [ ] C05 继续只补未完成，重试只补失败；已完成内容与人工修改不被隐式覆盖。
- [ ] C06 切页返回能恢复任务、进度、文档和编辑上下文；切换文件不接收旧文件的更新。
- [ ] C07 更换语言、术语表或模型时，明确作用于本轮还是下轮；续跑不得无提示混用参数。
- [ ] C08 重启后的恢复能力如实说明；若只支持同会话恢复，退出前允许保存，不承诺跨重启恢复。

### 2.4 字幕编辑

- [ ] S01 导入后能确认文件名、格式、编码、条数；乱码可修复，原文件保持完整。
- [ ] S02 中文/日文输入法选词的 Enter 不提交编辑；Enter / Shift+Enter / Esc 的语义清楚且一致。
- [ ] S03 ±100ms 快速点击不丢增量；起止时间合法；长小时值、重叠、多行、空行均可处理。
- [ ] S04 删除、拆分、合并、平移、校准可以撤销；缺少撤销时，对高影响操作提供预览/确认与备份。
- [ ] S05 全部重翻明确是否覆盖人工修改；队列期间允许哪些编辑有统一规则。
- [ ] S06 列表可截断，但详情可完整查看/复制/编辑；截断不得进入导出内容。
- [ ] S07 键盘能选行、编辑、打开菜单；右键菜单贴边仍可用；焦点关闭弹层后返回触发位置。
- [ ] S08 上千条仍顺滑；字号放大后虚拟行高与布局同步更新；ASS预览明确是模拟还是实际播放器效果。

### 2.5 导出

- [ ] E01 导出前明确格式、编码、仅译文/双语、完成范围；不能以成功外观输出空文件或含失败内容的“完成稿”。
- [ ] E02 用户取消对话框与成功可区分；真正写入成功后显示文件名与“打开所在文件夹”。
- [ ] E03 无写入权限、磁盘满、目标被占用有恢复建议；失败不破坏已有文件，覆盖前有保护。
- [ ] E04 SRT/VTT时间、ASS样式、多行、特殊字符导出后重新导入核对；格式不支持的信息损失提前说明。
- [ ] E05 外部播放器实际打开验证；对多音轨/多说话人/重叠字幕采用明确策略。
- [ ] E06 字幕与长文档对“成功、取消、失败、部分完成”使用同一套反馈语义。

### 2.6 术语约束

- [ ] G01 没有术语本时能创建/导入；有术语本能查看、修改、删除、导出，支持试译和示例格式。
- [ ] G02 空词、重复词、互相冲突的译名有定位；导入预览说明合并/覆盖策略；可撤销误导入。
- [ ] G03 明确大小写、边界、复数、变体及短词包含关系；产品名与普通词义不会机械误替换。
- [ ] G04 翻译前能看见当前选择与条数；主翻译、配音、长文档、字幕哪些支持术语，有明确说明。
- [ ] G05 术语表是模型提示还是强制替换必须如实表达；词条命中不等于全文译名一致。
- [ ] G06 结果给出未命中位置与可跳转原文；人工更正后只重试目标行/块；无出现的词条记“不适用”。

### 2.7 共通界面检查

- [ ] 错误消息说清发生了什么、保留了什么、可以做什么；不只输出异常栈或技术名词。
- [ ] 状态不能只靠红绿区分，配文字/图标；红色同时承担品牌、选中、错误时仍有足够区分。
- [ ] 重要文字对比度按真实背景检查；普通文本目标至少4.5:1；放大后不丢内容与操作。
- [ ] 用1180×700、1280×800、1680×1050，浅深主题、Windows缩放100%/125%/150%以及可用的文字/页面缩放实测。

对比度和文字放大参考 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 与 [Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)。这是验收参考，不是声称本应用已符合整个标准；系统DPI、浏览器缩放、应用字号档位应分别测量，不能互相代替。

### 4.3 评分和运行方法

1. 固定exe/提交版本、模型文件SHA256、量化、上下文、提示词、解码参数、术语表版本、GPU/驱动；冷启动与热启动分开记。
2. 普通翻译先做20条原创诊断，再做FLORES固定子集；另留未参与提示词调整的保留集。公开基准可能被模型见过，成绩不能等同真实泛化。
3. 人工逐项判断：准确性（否定、事实、数值、关系）、完整性（漏/增/重复）、术语、流畅、格式。关键事实错误单列，不能被平均分冲淡。
4. 自动核对只用于可定义不变量：JSON可解析与类型、时间合法、锚点完整、ID保留、文件可重导入。自然语言数值允许等价表达，必须归一化后比较。
5. 文学与歧义题允许多种正确答案；不确定的指代不能凭空补全。全文长度比仅作预警，不能单独判断漏译。
6. 配音每条跑3个预算；分别记语义保留、人工音节/拍数、自然度，再在有音频时记实际朗读时长。音节相同并不等于时长相同。
7. 对每条失败记录输入、输出、错误类型、严重度、可复现步骤；同材料比较改动前后。采样模式建议至少3次看波动，不能只选最好一次。

建议起始门槛（产品目标，尚未测得）：结构硬约束全部通过；关键否定/数字/主体关系错误为0；取消后已完成内容零丢失；重试不覆盖人工修改；其余质量目标以第一轮真实结果和人工审校校准。不要把这个小样本的零错误扩展成所有输入零错误。

## 5. 小范围迭代的具体例子

### 例A：修字幕串文档

给AI的任务：

> 只修复字幕工作台的文档隔离。已知后端CueProgress带docId，而前端只按cueIndex更新。先复现：打开B文档，注入A文档同一行号的done事件；B内容不得改变。为当前文档ID建立统一来源；所有异步快照返回前检查ID/请求版本，避免旧请求覆盖新文档。保留现有交互与导出契约。验收包括当前文档事件仍正常更新、切文件与快速切页无串入。

交付应含：修改文件、事件契约说明、修复前失败/修复后通过的复现证据、真实exe仍需补验的范围。别把它扩大成整页重写。

### 例B：修文档按钮与续跑

> 只收口文档导入→开始→运行→取消→继续→完成的状态。导入后可开始，提交中禁用重复开始，成功后清pending；取消保留完成块，继续复用同一ID；全量重翻使用明确的新任务或重置接口。中途改变方向/术语时清楚提示是否新建任务。用实际状态转换验证，不只断言按钮存在。

用户体验验收：导入38105字夹具，完成若干块后取消，记录完成块文本和ID；继续后完成块不变；完成时没有“开始翻译”；“重新翻译”会实际重新计算；切到模型页再回来仍能看到任务。

### 例C：术语维护的小闭环

> 实现“创建术语本→添加3词→Q08试译→修改一个译名→再次试译→导出”。先固定SaveGlossary数据类型和冲突策略，再接页面。空词、重复词、删除当前选中术语本有明确处理；列表、保存、导出相互一致。

先交这一个闭环，再扩展CSV批量导入。否则很容易同时生成多个界面，却没有一条从零可用的路径。

### 例D：阅读字号调整

> 保留三个字体家族与配色，仅调整长文档正文的角色字阶。先截图现状，用相同文章、同视口、同主题对比12px与15.5/16px；同时检查字幕表是否另需13.5/14px。放大后验证行高、工具栏、详情面板与虚拟化滚动。完成设计文档/token/使用页面同步后再更新相应视觉门禁，避免只改测试期望。

## 6. 字体与界面融合度

### 6.1 是否换字体

**当前不需要整体换字体，需要局部调整字号、数字字重与阅读布局。**

基于当前工作区实际截图：Public Sans的拉丁界面字、Noto Sans SC的中文、Geist Mono的功能数字，与直角、细线分区、红色强调、较强网格的方向基本一致。三种字各自承担界面/中文/时间码角色，数量本身不是问题。ASCII在中文句中使用拉丁字体是预期混排，关键是视觉大小与基线协调。

本次查看了主翻译台、模型中心、已载入字幕和文档页；浅色1180/1280/1680宽与深色1280宽均有截图。它们是Chrome mock页面，不等同于WebView2 + Windows实际DPI的最终清晰度。Playwright的deviceScaleFactor=2也不等于已验证Windows 200%缩放。

### 6.2 调整建议

| 项目 | 现状判断 | 建议 |
|---|---|---|
| 字体家族 | 基本协调 | 保留；不要为了风格再引入第四种标题字 |
| 长文档正文 | 核心文本用了12px caption，更像元数据；主翻译台已有15.5px阅读字阶，页面间角色不一致 | 文档对照正文试15.5/16px，行高1.7–1.9；建议先使用现成read token |
| 字幕表 | 12px正文、11px时间码，查看效率优先但长时阅读偏紧 | 正文试13.5/14px，时间码试11.5/12px；行高先评估56→64，再和虚拟化同步；两者均是待对比方案 |
| 数字字重 | 时间码/容量/速度局部很抢眼，长列有黑块感；属于截图观察 | 计量数字优先400，关键指标500；保留等宽，减少同一值再加粗；验证字体实际字重而非仅看CSS声明 |
| 状态条与辅助字 | micro固定11px，应用“较大”档不影响它 | 可保留紧凑默认，但提供可用放大方式；重要错误/取消反馈不得只放在微小状态栏 |
| 大写英文与字距 | SOURCE/OUTPUT等双语标签适合少量导航；信息已明显时会占空间 | 减少重复说明，字距只用于短英文标签；不对阅读正文或长中文标签统一加宽 |
| 内容密度 | 字幕左右区约1.55:1，未选中时右侧大量空白，译文列较窄；这是版面分配问题 | 详情面板可收起或拖拽；先把更多宽度给原译文，而不是用继续缩小字来容纳 |
| 小窗口 | 1180宽底部操作按钮会换行，顶部快捷键提示被裁；核心按钮本次测量仍在视口内 | 预先安排两行工具栏/更多菜单，折叠次要提示与历史栏；不把提示裁切夸大成所有按钮不可用 |
| 多语言回退 | CJK子集不覆盖全部繁体、生僻字、韩文；多语言翻译工具会经常遇到 | 用font-probe实际看缺字、行高、RTL；优先可靠系统回退，再考虑按语种打包字体；无需为追求同一种字形全量嵌入所有字库 |

现有字体许可分发已补到public/licenses与产物检查；本轮不重新把它当作未解决项。修改字阶要同步DESIGN.md、token、页面和真实截图验证，保留用户现有尚未提交的字体工作。

### 6.3 最小验收组合

同一份真实译文，浅/深主题 × 1180/1280/1680宽 × 标准/较大文字；额外在Windows100/125/150%DPI和WebView2实测。检查正文是否可读、按钮是否被遮、菜单贴边、长模型名、时间码对齐、中文输入法、繁体/韩文/RTL回退、复制后字符是否原样。

视觉判断以静态页面与真实使用任务为准；自动截图需等字体加载和入场淡入结束，避免把动画中间帧当成对比度失败。

## 本轮实现

| 范围 / 原问题 | 修改后的行为 |
|---|---|
| 文档开始与重复提交 I02 | 同步提交锁与准备状态，开始成功清除待提交文件；运行、停止、继续、完成分别呈现；终态事件前后端队列已结束 |
| 继续与全量重翻 I04 | 继续沿用同一文档和原参数，只补未完成块；重新翻译经确认调用新的 DocRestart，全量重新生成；按钮不再冒充续跑 |
| 切页恢复 I03 | 主翻译、字幕、文档保持挂载，保留任务、输入、输出、草稿、选中与滚动；隐藏页不响应快捷键、不显示其弹层 |
| 文档异步隔离 | 文件代次、文档ID和快照请求版本共同校验；旧文件的事件和迟到读取不能覆盖新任务；轮询补齐快照 |
| 主翻译取消 C01/C03/C04 | 从提交开始登记取消上下文；等待引擎加载时可结束本请求的等待；实际生成时传播取消。界面等待终态并保留部分译文；早到终态与重复提交有防护 |
| 字幕输入法 I05 | 组合输入和keyCode229期间Enter不提交；正常Enter提交，Shift+Enter换行；失败时保留编辑草稿 |
| 字幕撤销 I06 | 引擎维护按文档隔离的撤销/重做；覆盖文本、时间、删除、插入、拆分、合并、校准和样式；上限20步并限制历史体积，至少保留最后一步。按钮与Ctrl+Z/Y可用，输入框保留其原生撤销 |
| 字幕快速微调 I12 | 专用SubShiftCue在引擎锁内应用增量；前端同文档编辑顺序提交，连续点击不再发送旧时间绝对值 |
| 字幕菜单 I12 | Shift+F10/菜单键打开；方向键、Home/End和Esc；菜单限制在视口内；关闭返回列表焦点 |
| 字幕暂停/恢复与编辑 S05 | 暂停是完成当前条后停止推进，继续使用本队列原参数。编辑区在队列活动时禁用；编辑前需取消，界面有说明 |
| 字幕取消恢复 | 当前行取消后回到pending，避免永远卡在translating；后续可再次翻译。失败重试与指定行重试在同一锁内选择目标，只处理目标集；忙碌拒绝不改行状态 |
| 人工修改保护 C05 | 手改译文后，非空译文记为done，清空译文记pending；重试失败不会覆盖已人工改好的行。全部重翻会明确确认覆盖人工结果与清空历史 |
| 字幕修订号 | 快照、事件携带revision；编辑、撤销与队列更新递增。迟到的旧修订事件不能覆盖人工修改或撤销后的内容；旧请求仍受本地请求版本保护 |
| 导出结果 I17/E02/E06 | 字幕与文档统一返回实际保存路径；取消返回空串；成功后显示路径并提供打开所在文件夹。没有把用户取消提示为成功 |
| 导出文件保护 E03 | 同目录临时文件完整写入并同步后替换；保护导入原文件及其别名；失败保留已有内容。双文件先准备两份，替换失败尝试回滚，回滚受阻时保留备份并报告路径 |
| 部分导出 E01 | 字幕导出前确认格式、编码、双语模式、未完成行策略和格式损失；文档部分稿需显式确认，使用partial导出类型并保留未完成块标记；空稿拒绝 |

## 未执行与仍需验收的部分

新增 `frontend/scripts/verify-workflows.mjs` 有17项独立桥接夹具的用户流程测试，覆盖文档开始/续跑/重翻、乱序、主翻译早到终态/取消、IME、时间增量、撤销、菜单、导出、术语导入与退出保护。**执行请求被工具返回“用户拒绝”，所以没有运行，不计通过。**只进行了语法检查；状态记录在 `workflow-results.json`。没有通过把它加入verify:all来绕过拒绝。

因此，新增完整用户流程目前仍有验证缺口。可运行命令为在frontend执行 `npm run verify:workflows`；本轮不把脚本内容当作验收结果。

下列项目也不冒称完成：真实中文/日文输入法、Windows保存/覆盖/退出确认对话框、真实磁盘满与外部文件占用、下载断网/切源/跨重启续传、200%缩放及Windows125%/150%DPI、外部播放器与复杂ASS效果、CPU代表材料、真实OOM/驱动崩溃，以及翻译语义质量和术语人工审校。字幕仍以自动编码识别为主，没有新增手动重解码工作流；工作台没有跨重启自动恢复。

双文件导出可处理普通替换失败并回滚，但文件系统不提供本实现所需的跨两个路径的原子事务；断电或强杀恰逢两次替换之间仍需人工检查备份。此限制已与“单文件写完后替换”的保证区分。

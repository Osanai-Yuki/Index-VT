# 原创验收材料

2026-10-17为本项目评审创建；正文与台词为原创合成内容，不包含外部影视、书籍或数据集正文。外部素材的来源和待核对条件见上级评审文档。

这些文件是输入与检查点，**没有运行模型，也没有宣称模型已经通过**。short-cases的checks是语义约束，不是唯一参考译文；文学质量需人工判断。

## 使用

1. `short-cases.txt`供人工逐条复制。每次只粘贴该条text，不把题目编号或检查答案一同输入。`short-cases.json`供以后编排评测。
2. `structured-source.json`放主翻译台，开启JSON保持，要求只翻译自然语言字符串值，保留键、数值、布尔、路径、占位符。
3. `structure-source.md`可先在主翻译台开启Markdown约束试译；也可在长文档页测试默认行为，但两条路径的约束能力不能混为一谈。
4. `longdoc-story.zh.md`用于内容连贯；`longdoc-structural-stress.zh.md`用于分块完整性、取消续跑、ID和术语稳定性。后者38105个Python Unicode码点，低于50000字入口限制；上下文块数由实际配置决定。
5. `subtitle-challenge.srt`含12条字幕，有意保留一处合法重叠、多行、短时长和长台词。重叠本身不应一律判失败。另有UTF-16LE+BOM版本、VTT、ASS与LRC。
6. ASS含两个样式、`\N`、逗号正文、定位/斜体标签；不同格式能力不同。转换中不支持的样式应说明；不要要求SRT保留ASS专有信息。该夹具不代表支持完整ASS特效规范。
7. `glossary-reference.csv`是6条术语参考，不代表当前应用已经提供CSV导入界面；可在实现术语维护时使用对应映射。
8. `font-probe.txt`用于实际界面字形和Unicode复制检查，不作为翻译质量评分题。

## 结果记录

建议每次保存：case_id、应用版本、模型SHA256/量化、上下文、提示词/术语版本、解码参数、冷/热启动、TTFT、总耗时、显存峰值、输出、语义检查结果、人工备注。采样任务保留多次输出，避免只挑最佳结果。

建议把一部分后续真实材料作为不参与调提示词的保留集。固定词数或字符比只能发现异常线索，不能直接判断漏译。

## 重建与完整性

在仓库根目录运行：

```powershell
python docs/review-2026-10-17/materials/build-fixtures.py
```

脚本只写本目录的上述生成文件；重建会覆盖这些夹具。`manifest.json`记录文件SHA256与规模。手工编辑夹具后应同步检查点和清单，避免测试内容与预期分离。
